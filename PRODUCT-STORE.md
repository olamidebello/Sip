# Olamide product store

The 177 distinct product references mirror the supplied ProductList.pdf (August 2010): prepaid credits, variable-rate credits, basic/unlimited plans, bulk-minute plans, DIDs, additional incoming channels, VoIP hardware and support. Suggested Retail Price seeds the USD selling price. Reseller Cost remains private to tenant administrators. Repeated setup fees are deduplicated; countries sharing source product 121 have independent SKUs. Source page and original ID are retained in the bundled JSON. These are historical reference prices, not current provider quotations. Catalog prices are separate from the Flowroute 30% outbound rate markup.

After deployment, open Administration → Product catalog & orders → Import 177 reference products. Import is idempotent and preserves customizations. Review each draft, change name, description, reseller/selling/setup prices, billing interval and detailed service terms, then confirm provider availability and publish. Specify supported destinations, fair use, minute quotas, overages, DID eligibility, delivery/shipping/taxes and cancellation/refund conditions. Hardware models and worldwide packages require current availability review. Zero-priced variable credit templates must be customized before promising an included credit balance. Historical unlimited plans are not automatically implemented as live unlimited calling.

Users open Commerce → Products & services, filter/search, read terms, select quantity and purchase or subscribe. Server-authoritative prices and revision checks prevent stale price acceptance; a request key prevents duplicate submission. Orders snapshot their name, prices, terms and interval. Initial invoices include setup per unit; renewals exclude setup. Pay USD invoices through the existing configured Stripe hosted checkout and signed webhook. Free orders skip payment but still require fulfillment. The fulfillment status remains separate from payment status. Administrators record verified delivery/provisioning receipt only after payment. No automatic DID assignment, hardware shipping, switch plan activation or wallet credit is implied by an order or receipt.

Monthly, quarterly and annual subscriptions become active after verified fulfillment. A one-minute durable MySQL worker creates renewal invoices; it does not debit cards automatically. An advisory lock, transactional row locks and unique order/period records coordinate multiple replicas. An outstanding unpaid renewal pauses additional invoices. Renewal date starts from the current billing run, without historical catch-up charges. Stored prices apply until cancellation; product edits do not silently change existing subscriptions. Cancellation voids unpaid initial/renewal invoices and stops future renewal. Paid charges require separate refund handling and deployed services require decommissioning. Live suspension, refunds, taxes, prorating and automatic card subscriptions need their respective integrations.

Access is tenant scoped, requires billing permission, and honors tenant planRequests/adminPlans controls. Catalog costs are excluded from consumer API responses. Account deactivation pauses renewal. New tenants import the references through the same administrator action.

Run API tests and web build before deploying. Real Stripe test payments, tenant isolation, simultaneous orders, recurring invoice behavior and live fulfillment must be commissioned on staging before sale. The shared server must resolve publicly and the existing private gateway credentials must be configured.

## Publish all products using Ansible

Deploy the latest application image first so the API container contains productPublish.js. The play targets switch_nodes. Run as root on the application server using the bundled local inventory:

```bash
cd /opt/olamide/repo
ansible-playbook -i deploy/ansible/product-publish.local.yml deploy/ansible/publish-products.yml
```

Default scope is **every active tenant**. Suspended tenants are excluded. Use `-e product_all_tenants=false -e product_tenant_id=UUID` to limit execution to one tenant. Publication is atomic per tenant; if a later tenant fails, earlier completed tenants remain published and can be safely retried. New future tenants can be included by rerunning the playbook. Override `product_terms_source` with a controller-local UTF-8 terms file. `--check` previews without writes. Missing reference products are imported; current names, descriptions, prices and meaningful custom terms are preserved. Archived products remain archived unless `-e product_publish_archived=true` is explicitly set. Publication runs in one transaction and records a security event; rerunning does not increment unchanged products. Unknown or inactive tenants fail before modification. Root maintenance records a reserved system actor UUID (all zeros), rather than attributing the operation to a tenant user. The deployed schema must already be migrated. Publication makes products available for orders; it does not commission the underlying services or deliver hardware.
