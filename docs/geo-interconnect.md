# Geographic interconnect and rate controls

Deploy `deploy/ansible/geo-interconnect-local.yml` on the existing Olamide host. It integrates with the host's existing location, caller identity, SIP billing and carrier code; unfamiliar source layouts stop before source changes. Existing country boundary resources are required. The playbook backs up source and container images and restores them on failure. Additive policy/audit tables remain after rollback.

Super administrator controls:
- **Geographic trunks & rates**: enable the policy; add origin-country/provider rules for Flowroute or DIDWW; control trunk/rate availability, optional exact caller DID allowlists and multiple named radius zones. Each zone has its own enable switch and optional imported rate deck. An empty zone list uses country coverage; an existing list with no enabled matching zone denies access.
- Assign an imported deck to a zone to display the area's applicable destination rate. The zone deck overrides the country/provider rule deck. A selected imported deck is explicitly pinned even when a later import changes the global default; remove or replace its policy assignment to retire it. Deck ownership and provider must match the current tenant. Unassigned areas use the active default deck only when policy permits.
- A position and its reported uncertainty must fit fully inside a permitted circle. Overlaps with conflicting effective decks deny access. Missing, stale or insufficiently accurate session-bound location denies access when enabled. Users should refresh and renew location permissions after policy changes. GPS/IP policy is inherited from existing account settings. VPN is not a new requirement.
- Rate lookup includes the matched zone/country, uses the assigned deck and longest matching destination prefix. PSTN reservation uses the same geographic deck selection before wallet/trial reservation. Existing pricing calculations, including Flowroute cost plus 30%, remain in place. A preview is not authorization to call: caller DID, active carrier, destination restrictions, funds and capacity are checked when calling.
- **HP Inc Nigeria interconnect**: provider catalog registration (disabled), multiple named/individually enabled radius zones, exact caller DID list and eligibility simulation for destinations beginning `234`. This is staged administration, not live termination. HP SIP endpoint, authorized authentication, approved rate deck and switch adapter must be commissioned before live routing can be enabled. No HP route or invented credentials are installed.

Policies are tenant scoped, require `super_admin`, use optimistic version checks and append audit/security events. Users cannot set coordinates through these admin APIs. Device GPS is a policy input, not cryptographic proof of physical presence.

The source installer preserves local handlers, wallets, trials, VPN, firewall, TURN and Compose settings. It does not install a new SIP switch or alter host network rules. Tests cover location freshness, uncertainty, provider isolation, caller DID restrictions, overlap conflicts, rate deck selection, role checks and GUI payloads. Production two-way audio, carrier termination and end-to-end user location leases still require host/device verification.
