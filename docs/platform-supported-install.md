# Supported platform installation

`deploy/ansible/platform-supported-local.yml` updates the existing Debian production installation at `/opt/olamide/repo`. It is not a fresh-host bootstrap or an implementation of every item in the 86-feature catalog.

It installs host build/backup utilities, verifies the installed Docker Compose daemon and running MySQL/API/web stack, takes a private consistent InnoDB application-database dump and source/configuration archive, runs pinned Twilio-role/account-auth/readiness and DID availability installers, then applies the single Login/SignUp header last. Child stages run their API/UI tests and health checks. Existing additive migration paths create the supported tables. Successful stage receipts prevent unnecessary repeated rebuilds; `-e olamide_force_rebuild=true` forces them.

Twilio remote provisioning stays off. Super admin can save encrypted keys, inspect the account/services and create supported Verify/Messaging services later in Providers & Routing > Twilio. A read-only check does not prove create permission, phone delivery, SMS delivery or voice media acceptance. The existing 401/20003 rejection must be resolved with authorized account credentials. This installer does not replay uncertain provisioning jobs.

Reports and logs are root-only at `/opt/olamide/reports/platform-install`. `requirements.json` includes the complete source feature catalog, outstanding implementation IDs, installed integration files and schema evidence. It never promotes partial features to complete. No user secrets or provider secret values are included in that report. Logs and backup archives must remain private.

Daily root-only backups are enabled by default (`-e olamide_daily_backups=false` disables the timer). `/usr/local/sbin/olamide-platform-backup` can also run manually. Backups pause at 50 retained snapshots or less than 2 GiB free space; no original records or backups are automatically deleted. Monitor `systemctl status olamide-platform-backup.timer` and `journalctl -u olamide-platform-backup.service`. Export backups to protected off-host storage. These are application database/source snapshots, not whole-host backups: `/etc/kamailio`, RTPengine, external secret files and media stores require separate host recovery protection. Checksum/archive validation is not a successful restore test.

Each child deployment retains its own rollback images/source backups. The master stops at the first error. Earlier successful stages and additive schema changes remain; the installer never automatically rolls back a live database. Retrying skips completed stage receipts. Other deployment commands should not be run concurrently.

Still requires implementation and acceptance: live Twilio termination, transactional remote DID purchase/allocation, customer SMS/WhatsApp billing/submission, least-cost submission selection, PBX/media engine integrations, tax/template/commission workflows and the remaining catalog items. External provider onboarding and credentials cannot be generated from an Ansible script. No call/message/purchase, firewall opening, SIP policy bypass or automatic number allocation occurs here.
