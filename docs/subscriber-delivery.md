# Subscriber number delivery

After exact-head CI passes:

```bash
cd /opt/olamide/repo &&
git pull --ff-only origin main &&
bash deployment/deploy-subscriber-delivery.sh
```

Scope: SMS composed inside Olamide and calls placed through Olamide's authorized dialer. Administrator-enabled flowroute_sms_numbers bindings map a number to an active same-tenant subscriber with an eligible SIP authentication identity. Unverified signup profile phone numbers are not used to intercept traffic. Ambiguous matches do not route internally. Administrators must verify actual number ownership before assigning numbers.

Settings contains Subscriber SMS and calls: chat copy defaults on; email copy and number calls default off. Users can manage all three independently. Texts can deliver to chat, the recipient profile email, or both. Blocks apply. Chat plus email-queue creation commits atomically and a stable request key prevents duplicate internal chat copies on retry. Accepted internal delivery avoids external carrier dispatch and requires no external subscription. Nonmatching or disabled delivery falls back to existing authorized carrier SMS behavior, which requires a plan and an owned enabled sender number.

Additive MySQL tables store preferences, session-bound registration leases and SMS delivery/email jobs. The mail worker claims jobs atomically, rechecks active recipient/tenant and email opt-in, and uses configured Resend credentials with stable provider idempotency keys. There are at most five attempts with five-minute retry leases. A response means provider acceptance, not mailbox delivery. Provider failure does not undo an already committed chat copy. Email already accepted cannot be recalled. Message content is plaintext and this forwarding is not E2E encrypted. Inspect subscriber_sms_deliveries for mail attempts/status; no email provider is configured or secrets generated by this installer.

Calls to assigned numbers route to the local SIP identity only when the receiver enables number calls and a registration heartbeat is less than 75 seconds old, tied to an unexpired authenticated session. The browser sends its current confirmed SIP state every 30 seconds. Logout/session eviction invalidates eligibility immediately through the session join. This is client-reported registration freshness, not an authoritative registrar contact query; network/switch state may change before the INVITE. Existing tenant, DND, forwarding and external subscription checks still apply. No automatic second carrier call is made if an internally routed call fails.

This release does not rewrite inbound carrier/PSTN calls, inbound carrier webhook messages, SMS sent using a different native app, or email replies. Those paths require separate ingress and sender-identity handling. Test settings save/reload, both destinations, disabling mail before worker dispatch, duplicate request rejection, inactive/cross-tenant users, revoked/expired sessions, offline fallback and real two-way media. Deployment uses the existing backup/build/migrate/restart health workflow and preserves SIP configuration.
