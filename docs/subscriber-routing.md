# Subscriber SMS and number call routing

The SMS panel includes independent owner controls for email copies, SIP chat copies, preferring online subscribers when dialing a number, and accepting number calls on SIP. Incoming forwarding and SIP receipt default off. Email copies require a six-digit verification of the current profile email. Changing the profile email invalidates that destination until verified again.

Only active accounts assigned the number in the tenant's enabled Flowroute inventory or assigned DID inventory are eligible. Self-entered profile numbers never establish ownership. Ambiguous assignments do not route. Online means an unexpired registrar contact, not a manually selected presence label. DND, invisible presence and blocked contacts prevent number-to-SIP selection. External fallback retains existing subscription rules. Emergency and cellular calls on Android retain their existing Telecom path.

SMS is still sent through the carrier. Accepted outbound and authenticated inbound SMS enqueue optional copies. Email and chat are independent, deduplicated by provider event/channel/recipient and retried without resending the SMS. Workers recheck active membership, messaging access, blocks, current email verification and owner preferences. Unknown external senders appear in the SMS-in-SIP-chat inbox; known same-workspace senders appear in their existing chat thread. This is application chat, not a SIP MESSAGE wire gateway. No device interception of unrelated carrier texts or calls is performed.

Configure `SUBSCRIBER_ROUTING_ENABLED=true`, existing `RESEND_API_KEY`, `RESEND_FROM`, and `OTP_HMAC_SECRET` (32+ characters). For online routing set `KAMAILIO_LOCATION_RPC_URL` to a private authenticated JSON-RPC endpoint supporting `ul.lookup` with domain-aware location keys; optional `KAMAILIO_LOCATION_RPC_TOKEN` is sent as a Bearer token. Do not expose unrestricted Kamailio RPC to the Internet. Missing, failed or expired registrar queries fall back to existing routing. The web softphone uses its existing authorization endpoint to receive the selected SIP target; this change does not reroute arbitrary inbound PSTN calls at the switch or alter Android cellular Telecom routing.

Deploy a CI-approved checkout with `ansible-playbook -i inventory.ini deploy/ansible/subscriber-routing.yml -e subscriber_routing_enabled=true`. The imported release playbook verifies CI, backs up MySQL, runs additive migrations, rebuilds and checks HTTPS health. Disable with the same playbook and `subscriber_routing_enabled=false`; owners can individually switch off any control immediately. Registrar and mail secrets must be provisioned privately beforehand.

Validate on a test server with two subscribers: assigned number and online SIP call; offline fallback; recipient opt-out; blocked contacts; verified email; repeated carrier callbacks; separate email/chat copies; email outage retries. These source tests do not establish live carrier, mail, SIP media or Android hardware operation.
