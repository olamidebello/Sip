# Twilio signup and local login verification

This update adds an opt-in **account** authentication policy separate from caller-ID verification. No authentication policy is enabled by installing the code. A separate account Verify Service SID is required; the caller-ID Service SID cannot be reused by this policy.

Super admin > Twilio > Signup and login phone verification: load the policy, enter the account VA Service SID, choose SMS or voice, restrict dialing prefixes, set a daily cap, then enable signup and/or local-password login verification. Service ownership is checked before saving. Configure and test account phone delivery before requiring it for all local password sign-ins. Existing sessions remain valid. Passkey and LDAP authentication retain their current independent policies; this update does not add an OTP step to those routes.

Signup creates a pending account with a hashed PIN when required. The SIP account is not created until Twilio approves the bound account-phone challenge. If delivery fails or is uncertain, use Resume phone verification with the signup email, password and PIN after the cooldown. It does not silently activate accounts or resend messages. A six-to-eight-digit nontrivial PIN supplements the password; it is not a password replacement. Existing accounts without a PIN can still complete password + OTP and enroll under Account PIN. Enrolling/changing a PIN requires the current password, existing PIN if enrolled and a fresh phone OTP. Loss of both PIN and access to the phone requires a separately reviewed account-recovery process; no recovery bypass is introduced here.

Password sign-in verifies password and any enrolled PIN before issuing a phone challenge. A pending response is not a session. The code must be approved against the exact persisted Twilio Verification SID, account, service, phone, user, tenant and purpose. Challenges expire after ten minutes, allow five checks, and are consumed once. PIN attempts lock for fifteen minutes after repeated failures. Send reservations include unknown submissions, with a per-user cooldown/hourly cap and per-tenant daily cap. Existing server edge rate limits remain in effect. No plaintext PINs or OTPs are persisted in these tables or logged.

The preserving installer stages all source changes before writing and stops on unknown anchors. Backend and browser tests use mocked provider/DB responses; they do not prove real SMS delivery. Production database migration, actual Twilio delivery, CAPTCHA signup, PIN enrollment, successful/failed login and logout still need live acceptance checks after deployment. No calls, SMS messages or account changes have been made against the production server while developing this update.

Separate outstanding work: live trunk termination, automated DID purchase/allocation, customer SMS/WhatsApp billing and reconciliation, least-cost routing, business onboarding/PBX/call-center controls and consolidating navigation into one sign-in entry are not implemented by these account-auth files.
