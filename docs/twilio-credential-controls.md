# Super-admin Twilio API and key controls

Install `deploy/ansible/twilio-credentials-local.yml` on the existing host. It preserves the installed Twilio hub and UI instead of replacing them, so DID checkout, role management and readiness additions remain intact. It adds one `twilio_credential_tests` table, runs API/UI tests and verifies application health. Deployment does not change saved credentials, provision remote resources, make paid purchases or send calls/messages.

Open **Super admin > Providers & Routing > Twilio > API keys · status, access tests and removal**. Use the existing credential form above it to add/replace the Account SID, Auth Token, API key pair, Verify/Messaging Service IDs and separate SendGrid/Segment credentials. Empty fields preserve saved values. Encryption uses the existing server-side `PROVIDER_CREDENTIAL_KEY`; an unavailable encryption key must be restored through server operations. Saved secret values are never returned by status/history APIs or filled into browser inputs.

The status panel shows configured fields, REST authentication choice and caller-ID verification credential readiness. REST prefers the API key pair when present. Caller-ID voice verification requires the Account Auth Token and configured Verify Service. Explicitly removing the API key pair can switch REST to the saved Account Auth Token; the UI requires confirmation describing this change. Removing the last usable credential requires disabling the integration. Clear-all disables the integration and removes local saved fields; it does not revoke keys or delete resources on Twilio. Revocation/remote key creation/rotation are not implemented by these local removal controls.

Read-only tests check Account, Verify inventory, Messaging inventory, Trunk inventory, Owned Numbers and country Number Pricing. Each result includes a sanitized HTTP/provider error code if available. The latest five reports are shown with the tested settings version; reports for old versions are identified. No alternate credentials are attempted on failure. A successful read does not prove write permission, number purchase, live delivery or audio. SendGrid and Segment APIs are separate and are not tested here. Existing per-role controls can inspect configured individual services.

Credential saves/removals use the existing tenant lock, optimistic version check, encrypted persistence and security-event audit. Test reports are tenant scoped and super-admin only, and do not contain credential or remote response bodies. Disabling the integration stops dependent operations and can cause due Twilio DID leases to release through the installed rental worker; it does not immediately revoke remote keys or remove all remote resources. Review the confirmation and existing rental states before disabling.

The deployment keeps source/image backups and restores them on failure; it leaves additive schema/history intact. Local tests mock provider responses and database boundaries. Live permissions and provider acceptance still need testing with the authorized account after deployment.
